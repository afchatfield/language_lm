# Running Phase 3 on the H200

Three commands from a fresh clone. Everything else is derived.

```bash
git clone <repo> && cd language_lm
make setup-cuda && conda activate langlm
make phase3
```

`make phase3` runs `train-data`, then `dry-run`, then `train`. The adapter lands
in `checkpoints/phase3-de/`.

## What each step does, and how long it takes

| Step | What | Time |
|---|---|---|
| `make setup-cuda` | conda env from `environment-cuda.yml` | ~5 min |
| `make train-data` | Falko-MERLIN + Leipzig download, freeze splits, Hunspell dictionary, clean corpus, 30k training examples | ~30 min, mostly the spaCy passes |
| `make dry-run` | loss mask, output schema, one forward pass | ~1 min |
| `make train` | 3 epochs LoRA over 4.13M tokens | ~15-25 min |

Under an hour end to end, and most of it is data preparation rather than
training.

## Why the data is rebuilt rather than shipped

`data/` is gitignored: everything in it is downloadable or derived. The
generation is seeded (`configs/phase2.yaml`), so rebuilding on the server
produces byte-identical output to the local build — the split manifest's
SHA-256 for `clean_de` is the check on that, and `make train-data` will fail
loudly if it does not match.

If the corpus downloads are blocked on your network, copy the two derived files
across instead and skip `train-data`:

```bash
scp data/processed/training/de.jsonl   h200:~/language_lm/data/processed/training/
scp data/processed/clean_de/de.m2      h200:~/language_lm/data/processed/clean_de/
scp data/splits/manifest.json          h200:~/language_lm/data/splits/
```

That is 26MB. The training set alone is enough for `make train`.

## What is *not* needed on the server

* **LanguageTool.** No Docker, no n-grams, no 6GB download. It is only used to
  build `reports/phase2/lt_rule_survey.md`, which is already committed.
* **MLX.** Apple-only, and absent from `environment-cuda.yml`.
* **The n-gram data.** Same reason as LanguageTool.

## The one thing to look at before walking away

`make dry-run` prints the loss mask:

```
loss mask: 36 prompt tokens ignored, 8 answer tokens supervised (18% of the sequence)
  supervised text: {"edits": []}</s>
```

The supervised text must be the JSON answer and nothing else. If the prompt
appears there, the run will teach the model to generate German learner
sentences — the input side of the corpus, which is the opposite of the task —
and it will look like a normal run the whole way through. `make train` prints
the same line before it starts, so there is no way to launch without seeing it.

## Configuration

`configs/phase3.yaml`. The defaults are the roadmap's: r=32, alpha=64, all
linear layers, lr 1e-4, cosine, 3 epochs.

Two choices worth knowing about:

* **bf16, not 4-bit.** A quantised base trains roughly twice as fast, but Phase
  4's ablation table has an "uncompressed" row and it is not uncompressed if the
  model was trained quantised.
* **Adapter saved separately, not merged.** Phase 4 operates on the base
  checkpoint and re-applies the adapter.

## Overrides

```bash
python scripts/train_sft.py --epochs 2 --batch-size 32
python scripts/train_sft.py --limit 2000        # a quick sanity run
```

## Measured local numbers, for comparison

Benchmarked on the M1/16GB, LoRA r=32, batch 4 x seq 256:

| Setup | Throughput | Peak memory |
|---|---:|---:|
| PyTorch MPS bf16 | 32 tok/s | 12.1 GB |
| MLX bf16 | 24 tok/s | 9.2 GB |
| MLX 4-bit base | 77 tok/s | 6.9 GB |

Three epochs of this corpus on the M1 is about four days in bf16. That is why
Phase 3 runs on the H200.
